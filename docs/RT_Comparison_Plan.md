# 独立实时光追与光栅切换实施计划

日期：2026-10-09。状态：用户“推进光追管线”已确认完整方案，含RT Pipeline＋SBT；RT-A/B/C已实现并验证；下一项RT-D降噪与整体验证。

## 已确认目标

先实现独立实时光追，再由用户观察与传统光栅的差别。当前已交付的光栅、GTAO和厨房修复继续保留；自建CPU对象BVH、Hi-Z、indirect/LOD、网格SDF/距离场顺序后移。硬件RT必须使用的BLAS/TLAS在RT阶段建设，不属于延期的CPU可见性BVH。

- 光追和光栅分别建渲染管线，RT独立发射相机主光线。Q11“独立一个光追管线和光栅化管线分开”按Vulkan RT Pipeline＋Shader Binding Table（SBT）理解，用户后续“推进光追管线”确认该实施方向。
- 共享场景、几何、材质及光学参数、灯光、相机、曝光和显示变换；各自计算可见性和光传输。不会为一条路径单独调整光源强度、曝光或材质来制造对照。
- 首轮光追目标含阴影、反射、多反弹GI和基础实体玻璃，分阶段交付。仅建立光线求交不等于这些效果已完成。
- 画质优先，允许静止累积和工程用高采样参考；主画面优先降噪实时输出。初版RT没有硬FPS门槛；正式观察/数据固定1920×1080，预览可降低采样或分辨率。
- 首轮场景为厨房，并使用解析小场景验证正确性；Helmet/四合院后续扩展。
- UI首轮只增加“光栅 / 光线追踪”渲染方式切换。分屏、拖动分割线、成对截图工具后置；本阶段不会同时持续渲染两条路径。
- 用户先自行判断画面；只有明确要求助手判断时，才给画质优劣或技术排名。工程仍验证错误、数值、同步、耗时及内存。

## 玻璃和降噪边界

闭合且通过内容验证的网格采用实体介质，首轮实现折射、Fresnel反射、全反射和按路径长度的吸收。开口网格明确使用薄片模型并提示，不自动补洞或猜测厚度。焦散专项算法、嵌套介质和体积散射后置；普通路径采样中可能偶然出现的焦散不作为已验收的焦散能力。

两条路径共享IOR、透射和吸收等参数。RT处理进入/离开介质；纯光栅使用屏幕/探针近似并注明覆盖限制，不在光栅玻璃中偷偷调用RT。厨房core资产没有KHR_materials_transmission/volume/ior，但extras.pbrt保留明确dielectric类型和eta=1.5；只为明确光学语义做适配，不把全部alpha BLEND误认作玻璃。原始资产保持，内容判定和近似语义进入导入/准备诊断。

用户选择接入成熟降噪库；首选NRD。实施前固定版本、许可/来源与Linux/Vulkan构建依赖，按项目接口接入，不替换整个引擎RHI。NRD官方明确主要针对不透明表面，不原生覆盖透明/体积；玻璃透射单独处理，辅助特征必须描述与信号一致的实际表面/运动。无法可靠降噪的透射信号显式回到自己的累积/历史策略并报告限制，不强行套首层不透明法线或复用光栅TAA。完整RT阶段验收须覆盖玻璃透射在静止、移动及遮挡显露下的行为。

## 资源、同步与精度合同

共享Renderer持有帧提交、资源退休和最终显示职责；分别封装光栅与RT场景计算路径，避免Application调度每个内部pass。RT读完整场景而非相机剔除后的光栅draw list，保留对象稳定身份及相同可见性/单双面/alpha语义。厨房光卡的primary/shadow/emission角色分开处理；光源定义与代理近似明确记录，不能因RT看到原始光卡就重新堵住窗户。RT间接光不叠加光栅probe SH/AO来重复计算同一贡献。

- GPU场景数据：实例到几何/材质/纹理索引，明确Vertex当前112B布局与位置偏移，使用有检查的GPU布局；材质贴图具备RT访问权限。
- AS：每网格BLAS与实例TLAS；静态初建，刚体移动更新实例/TLAS；重建/候选失败保留旧可运行场景；AS、SBT和场景表直到引用提交完成才退休。
- 图依赖：上传→AS构建输入，BLAS构建→TLAS构建，AS写→RT读，RT storage image写→降噪读写→显示采样。扩展现有图的AS/RT/storage-image状态，沿用单队列，按成功提交发布状态。
- 独立RT HDR、采样计数/累积、深度/法线/粗糙度/运动/命中距离/信号与降噪历史，不复用光栅的可见性缓冲或TAA历史。未选中的路径不持续执行。
- 模式切换、场景/材质/灯光变化、相机跳变、resize、采样设置改变等有明确失效规则；两帧在飞行时隔离可变数据。禁用RT或准备失败可继续光栅并显示原因。
- 初始候选：主HDR RGBA16F、累积FP32/计数及必要FP32几何特征；实际格式按设备能力、NRD编码合同和精度测试选择。光线起点/最小距离偏移与几何尺度关联；几何法线区分着色法线，不任意翻转模型法线。

## 验证与证据

先写每个增量的实际资源/同步/精度决定，再实现。只增加覆盖真实风险的解析或集成测试：三角形/闭合盒命中、变换与alpha mask、玻璃解析规律、静态路径参考、历史失效与两帧并发、失败保留、资源最终归零。沿用已交付厨房/光栅回归，RT能力不可用时明确跳过RT测试而不宣称硬件成功。

RTX4060Ti实际运行记录RT trace/AS build-update/降噪/输出成本，区分CPU、GPU与present等待，记录稳态和构建峰值内存；不使用其他GPU示例耗时作为本机验收。正式1080p配置及源代码/资产身份固定。原始HDR/高采样参考仅作工程验证证据，UI仍只做渲染模式切换。不主动评价哪条路径更好。

既有宽范围运动、长时间预算、validation/Wayland及WSI历史问题不因RT规划自动关闭；若图形增量触及它们再作相关验证。
