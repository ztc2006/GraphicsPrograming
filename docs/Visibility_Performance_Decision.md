# 厨房可见性与性能增量：实施前决定

2026-10-08。目标为现有静态 glTF/GLB/OBJ 路径、RTX 4060 Ti、原生 1080p。
先减少不产生可见结果的绘制，再继续 M6-C/GTAO。保留材质、曝光、灯光、阴影精度、
动态/透明语义和当前单队列帧资源；本轮不通过降低画质取得性能数字。

## 决定与替代方案

采用共享的保守 CPU AABB/六平面测试：默认打开相机视锥剔除，
每个 CSM/聚光灯 tile 独立筛选完整场景的投影者。主相机剔除后的列表不能作为阴影候选，
否则离屏对象会失去投影。缺少/非法 bounds、非法平面保留对象；边界包含并使用浮点误差余量。
legacy 单阴影图第一轮保留原完整候选路径。保留相机和阴影独立开关用于数值/画面/耗时配对。

不立即引入 Hi-Z occlusion、GPU-driven 或深度预通道：它们需要新资源、反馈/间接提交、
历史/遮挡显露处理，当前还有便宜而未开启的可见性检查。近到远排序独立评估，
避免本轮混入 coplanar/depth-tie 顺序差异。共享 helper 替代 Application 的私有平面实现，
保证 Vulkan ZO 近/远平面约定和阴影使用相同测试。

## API 中立数据流和资源

当前场景完整实例/更新后的世界 AABB → 相机可见列表 → 主渲染。
完整 opaque/mask → 各光源/级联 clip volume → 相应阴影 tile 的可见候选。
完整实例仍输入提交序的运动历史、资产退休和探针几何身份；只改变被记录的 draw 数量。
不新增 GPU buffer、image、descriptor、pipeline 或 pass，不改变 shader/UBO/push ABI 或同步。
CPU 每候选最多六平面测试；平面提取采用 double，输入仍为生产 float VP，
AABB 测试给出按系数/坐标量级缩放的保守误差。阴影 XY 增加一个 texel 的保守范围，
摄像机继续采用现有最大半像素 jitter 扩展。

## 呈现诊断边界

同一小场景/同一进程，测试窗口可见→隐藏工作区→重新显示：
隐藏阶段 acquire 中位数 995.712ms，慢帧只位于隐藏阶段，重新显示恢复正常刷新。
因此本轮的 ~1Hz 症状能由窗口可见性触发，无需更改 TAA 或资源同步。
不得由此宣布所有历史 legacy/EXT 超时已解决；这些用例需要在确认可见的窗口下重新运行。
GPU 基准记录窗口状态、保留所有慢帧；不能删除等待或锁高时钟掩盖问题。

## 验证

- CPU：Vulkan 六个 clip 边界、边界接触、perspective/ortho、jitter guard、非法 bounds/矩阵保留、
  大坐标与反射/非均匀缩放的保守性。
- 生产 GPU：有阴影的完整厨房多个固定视角、离屏投影者、边界物体、mask；
  全绘制/主剔除/阴影剔除/两者开启的 HDR 回读必须一致或仅有明确的浮点量化容差。
- 可见窗口下原生 1080p 对照 Main/Shadow/query/draw counts；有效查询、场景资源和呈现退休正常。
- 相关 CSM/indoor/motion/TAA/异步加载回归，legacy/EXT 原120秒上限不增加。
- 出现丢失阴影/边界闪烁或无实际收益时，不以更少 draw calls 作为成功理由。

依据 RTR4 第18章可见性、第20/23章有效着色/性能和第22章保守包围体测试。
本轮采用书中稳定的可见性原则，不引入新的外部图形算法依赖。

## 数值对照后的范围调整

三个厨房视角的完整相机/阴影/联合剔除 HDR 结果逐像素一致。
默认视角 caster frustum 筛选仅 1758→1707，因此继续减少未被接收面使用的级联。
对每级按 shader 的 view-depth 区间加上前一级混合带，与主 opaque/mask/blend 世界 AABB
做保守投影测试；没有任何可能的接收面时保持该 tile 已清为远深度并跳过投影者绘制。
所有离屏投影者仍来自完整 allOpaque/allMask，不能用接收面列表代替投影者。
缺少/非法接收面 bounds 保留级联；shadow debug 和 probe capture 保留完整 tile 路径。
CPU 相机位置/允许状态放在 frame context，GPU ABI/资源数量不变。
另补 debug tile 与 probe 重捕获的生产 HDR 对照，避免只验证普通主画面。
